## Notes

- **`<esi:inline>`** – Fully supported. Body content is output verbatim without further ESI processing, serving as an escape hatch for literal ESI markup.
- **`<esi:choose>`, `<esi:when>`, `<esi:otherwise>`** – Fully supported. Boolean `test` attributes (`true`/`false`/`0`/`1`) select the first matching `<esi:when>` branch. If no branch matches, `<esi:otherwise>` is rendered (if present). `$(...)` variables in `test` are resolved before evaluation. Supports nested `<esi:choose>`, `<esi:include>`, `<esi:try>`, and `<esi:vars>` inside branch bodies.
- **`<esi:try>`, `<esi:attempt>`, `<esi:except>`** – Fully supported. Unhandled include errors within `<esi:attempt>` trigger `<esi:except>` rendering. `onerror="continue"` and fallback body do NOT trigger `<esi:except>`. Supports nested `<esi:try>` blocks.
- **`<esi:vars>` / `$(...)` variable substitution** – Fully supported. Variables are defined via `<esi:variable>` in `<esi:vars>` blocks and resolved via `$(NAME)` syntax in include URLs, text content, and test expressions. Supports `$(HTTP_HEADER{Name})`, `$(HTTP_COOKIE{name})`, and `$(QUERY_STRING{param})` via config fields.
- **Nginx** – Uses `ParseWithConfig` from `libgomesi` (migrated from `Parse`). SSRF blocking is configurable via `mesi_block_private_ips` (default `on` — see BREAKING CHANGE in CHANGELOG), and a hostname whitelist via `mesi_allowed_hosts` (one quoted, space-separated string — same convention as `mesi_cache_memcached_servers`; content mirrors Apache's `MesiAllowedHosts`; exact or subdomain-suffix match with a `.` boundary that rejects suffix injection; unset = no restriction, backward compatible; whitespace-only values — ASCII or Unicode (e.g. U+00A0) — are rejected at config load so an operator's restriction can never silently tokenize to an empty allowlist, and invalid UTF-8 never counts as whitespace (#354)). The AllowedHosts hostname check runs first, then the dial-time private-IP block — two-phase defense-in-depth (#199). Redirect targets are re-validated against the whitelist on every hop (an allowed backend cannot redirect to a host outside the list), and relative includes resolve against the request's Host header first — the resolved host is subject to the whitelist as well. Cache keys are scoped by the SSRF policy (AllowedHosts + BlockPrivateIPs + AllowPrivateIPsForAllowedHosts) and the client type (custom vs default HTTPClient), so content cached under one policy is never served under a different one, and the per-include fetch timeout bounds the whole redirect chain rather than each hop. Each `<esi:include>` fetch creates its own HTTP client (no shared client / connection pooling in the nginx module). The global ESI nesting depth is configurable via `mesi_max_depth` (unset → 5, explicit `0` = passthrough, range `[0, 10000]` validated at config load — see the dedicated `mesi_max_depth` note, #180). Cache backends: in-memory, Redis (`mesi_cache_redis_addr`, `mesi_cache_redis_password`, `mesi_cache_redis_db`), and Memcached (`mesi_cache_memcached_servers`).
- **PHP Extension** – Exposes `\mesi\parse(input, max_depth, default_url)` (legacy, no security configuration; `max_depth` range `[0, 10000]`, explicit `0` is passthrough, out of range → `E_WARNING` + `false` since #414) and `\mesi\parse_with_config(input, max_depth, default_url, config)` which supports `block_private_ips` (defaults to `true` — SSRF dial-time blocking of private/reserved IP ranges) and `allowed_hosts` (space-separated hostname whitelist; empty/absent = all hosts allowed; exact or subdomain-suffix match with a `.` boundary that rejects suffix injection; case-insensitive; ports ignored; passed verbatim to libgomesi's `ParseWithConfig`). The whitelist check runs by hostname before the dial-time private-IP check and does NOT bypass it — includes to private/reserved IPs still require `block_private_ips => false`. Non-string, control-character and whitespace-only (ASCII or Unicode) values are rejected with `E_WARNING` so a restriction can never silently tokenize to an empty allowlist (#190). Since #238 `parse_with_config()` also supports `cache_key_template` (`${url}`, `${header:Name}`, `${cookie:Name}` via `mesi.BuildCacheKey`; unknown placeholders left literal; empty/absent = URL-only key; silently ignored when no cache backend is configured) together with `request_headers` / `request_cookies` request context. Since #242 `parse_with_config()` also supports `shared_http_client` (bool/int, default `true` — backward compatible): `true` routes include fetches through libgomesi's process-wide shared HTTP client (TCP/TLS connection pooling, always-on before #242 via MINIT `InitHTTPClient`); `false` detaches it (`FreeHTTPClient`) and every fetch builds its own client from the parse-time config, with `block_private_ips` then honoured per parse — the setting is process-wide state, last call wins until changed (a non-boolean value is rejected with `E_WARNING`). Since #181 `parse_with_config()` also supports `timeout` (integer seconds, range `[1, 86400]`, absent → `30`; `0`/negatives/non-integers rejected with `E_WARNING` + `false`) — see the dedicated `timeout` note below. The legacy `parse()` entrypoint keeps the module-init behaviour (no blocking) until a `parse_with_config()` call opts in, and keeps the hardcoded 30s fetch timeout.
- **Caddy / FrankenPHP** – FrankenPHP uses the Caddy plugin, identical functionality.
- **Caddy `max_depth` (#401)** — Global ESI nesting depth via the `max_depth` Caddyfile/JSON field. Unset → `5`. Explicit `0` is valid passthrough (no ESI fetch); `1` processes one include level so the inner tag is replaced with the empty `IncludeErrorMarker`. Range `[0, 10000]` (`mesi.MaxMaxDepth`). Invalid values (negative, non-numeric, above the cap) are rejected at Caddyfile parse and JSON provision — no silent default and no `uint(-1)` wrap.
- **libgomesi / PHP `maxDepth` (#414)** — `Parse` / `ParseWithConfig*` reject `maxDepth` outside `[0, 10000]` (`mesi.MaxMaxDepth`) and return NULL (logged at Warn via libgomesi's default logger). Explicit `0` is passthrough (no ESI fetch). PHP `\mesi\parse()` / `\mesi\parse_with_config()` reject the same range with `E_WARNING` + `false` (and treat a NULL from libgomesi as `false`). Matches Apache `MesiMaxDepth` (#166) / Caddy `max_depth` (#401). Core `MESIParse` still does not cap a Go caller's `MaxDepth`.
- **Proxy** – Accepts full `EsiParserConfig`; all features available when provided by calling code.
- **AllowedHosts (libgomesi)** since #357 – `ParseWithConfig`/`ParseWithConfigEx` tokenize the `allowedHosts` string with `strings.Fields`; an empty string keeps the documented "no restriction" semantics. A non-empty but whitespace-only value (ASCII or Unicode whitespace, e.g. U+00A0) tokenizes to zero hosts and is logged as a misconfiguration — `WARN allowed_hosts_empty_after_parsing` on stderr via libgomesi's default logger (the C ABI has no logger parameter), Warn severity, with a Debug fallback for programmatically supplied loggers without `LoggerWarn` — so the restriction can never silently fail open at the shared-library layer; restriction behavior itself is unchanged. Platform modules that reject such values earlier, at their own config load (nginx #354, PHP extension #190), never reach the diagnostic; Apache does not yet reject them (#358).
- **AllowedHosts (CLI)** – Exposed via the `-allowed-hosts` flag: a comma-separated host whitelist passed verbatim to `mesi.EsiParserConfig.AllowedHosts`. Matching is handled entirely by the shared core — exact or subdomain-suffix match with a `.` boundary that rejects suffix injection, case-insensitive, ports ignored. Unset/empty = all hosts allowed (backward compatible), subject to the dial-time private-IP block (`-allow-private-ips`); the whitelist check does NOT bypass `BlockPrivateIPs`. Entries are matched as written — separate hosts with commas only (#179).
- **AllowedHosts (RoadRunner)** since #203 – Exposed via the `allowed_hosts` YAML list (`mesi.allowed_hosts: [backend.internal, cdn.trusted.com]`), passed verbatim to `mesi.EsiParserConfig.AllowedHosts`. Matching is handled entirely by the shared core — exact or subdomain-suffix match with a `.` boundary that rejects suffix injection, case-insensitive, ports ignored. Unset/empty list = all hosts allowed (backward compatible), subject to the dial-time `block_private_ips` check (default `true`); the whitelist check runs by hostname first and does NOT bypass `BlockPrivateIPs` — includes to private/reserved IPs still require `block_private_ips: false` (two-phase defense-in-depth). An entry that matches nothing (e.g. an accidental empty string) makes the list fail closed rather than open.
- **AllowPrivateIPsForAllowedHosts (RoadRunner)** since #209 – Exposed via the `allow_private_ips_for_allowed_hosts` YAML bool (default `false`), passed verbatim to `mesi.EsiParserConfig.AllowPrivateIPsForAllowedHosts`. When `true`, hosts listed in `allowed_hosts` may resolve to private/reserved IPs (the dial-time block is bypassed for them); the whitelist check still runs first and the bypass is only effective when BOTH `block_private_ips: true` AND `allowed_hosts` non-empty are set — otherwise a no-op. **Trusts DNS** (same security profile as Apache `MesiAllowPrivateIPsForAllowedHosts` #168). No effect under `shared_http_client` — the shared transport bakes `block_private_ips` at startup, so the bypass is not consulted for shared-client fetches (documented limitation).
- **AllowPrivateIPsForAllowedHosts (nginx)** since #204 – Exposed via the `mesi_allow_private_ips_for_allowed` directive (NGX_CONF_FLAG, default `off`), passed through libgomesi's `ParseWithConfigEx` 6-arg entry point (older `libgomesi.so` builds fall back to `ParseWithConfig` and warn that the bypass is disabled). When `on` with BOTH `mesi_block_private_ips on` AND a non-empty `mesi_allowed_hosts`, listed hosts may resolve to private/reserved IPs; otherwise a no-op. **Trusts DNS** (same security profile as Apache `MesiAllowPrivateIPsForAllowedHosts` #168). Because the nginx module builds per-request HTTP clients, the bypass is fully effective — no shared-transport startup-baking limitation (unlike Apache/RoadRunner shared HTTP client).
- **AllowPrivateIPsForAllowedHosts (PHP extension)** since #196 – Exposed via the `allow_private_ips_for_allowed_hosts` config key for `parse_with_config()` (bool, absent = `false`; non-boolean rejected with `E_WARNING` + `false`). The extension calls libgomesi's `ParseWithConfigEx`; **bypass-flagged parses detach from the shared HTTP client** (the shared transport bakes `block_private_ips` at startup, which would silently negate the bypass) and use per-request clients — no connection pooling for those parses; the shared client still serves non-bypass parses. Only effective when BOTH `block_private_ips => true` AND a non-empty `allowed_hosts` are set; otherwise a no-op; unlisted hosts and empty whitelists can never bypass (fail closed). **Trusts DNS** (same security profile as Apache #168). The same libgomesi detachment retroactively makes the Apache #168 bypass effective when `MesiSharedHTTPClient` is `On`.
- **AllowPrivateIPsForAllowedHosts (Traefik)** since #205 – Exposed via the `allowPrivateIPsForAllowedHosts` plugin config bool (default `false`), passed verbatim to `mesi.EsiParserConfig.AllowPrivateIPsForAllowedHosts`. Only effective when BOTH `blockPrivateIPs: true` AND a non-empty `allowedHosts` are set; otherwise a no-op; unlisted hosts and empty whitelists never bypass (fail closed). **Trusts DNS** (same profile as Apache #168). No effect under `sharedHTTPClient: true` — the shared transport bakes `blockPrivateIPs` at startup (same limitation as RoadRunner #209). **Yaegi note:** under the interpreted plugin the dial-time IP-blocking transport is stubbed (`ssrf_dialer.go` removed in the Dockerfile), so enforcement — including the bypass — is not active there; URL-level `allowedHosts` remains the effective control; proof lives in plain-Go unit tests.
- **AllowPrivateIPsForAllowedHosts (CLI)** since #182 – Exposed via the `-allowPrivateIPsForAllowedHosts` flag (bool, default `false`), mapped to `mesi.EsiParserConfig.AllowPrivateIPsForAllowedHosts`. Only effective when the private-IP block is active (`-allow-private-ips` NOT set → `BlockPrivateIPs` true) AND `-allowed-hosts` is non-empty; otherwise a no-op; unlisted hosts and empty whitelists never bypass (fail closed). **Trusts DNS** (same profile as Apache #168). No effect with `-shared-http-client` — the shared transport bakes the private-IP policy at startup (same limitation as RoadRunner #209).
- **AllowPrivateIPsForAllowedHosts (Caddy / FrankenPHP)** since #256 – Exposed via the no-arg Caddyfile directive `allow_private_ips_for_allowed_hosts` (present = enabled) and the JSON field `allow_private_ips_for_allowed_hosts,omitempty`; default `false` via zero value. Only effective when `block_private_ips` is enabled (the middleware default) AND `allowed_hosts` is non-empty; otherwise a no-op; unlisted hosts and empty whitelists never bypass (fail closed). **Trusts DNS** (same profile as Apache #168). No effect under `shared_http_client` — the shared transport bakes the private-IP policy at startup; the shared client is opt-in in the Caddy module, so the default per-request path gets the bypass (same limitation as RoadRunner #209 when opted in).
- **IncludeErrorMarker (CLI)** – Can only be set programmatically (no CLI flag).
- **`fetch-mode="ab"` (`ab-ratio`)** – Format requirements enforced since #315:
  - Exactly one `:` separator (`A:B`); leading and trailing whitespace is trimmed.
  - Each side must be a non-negative unsigned integer.
  - Either side may be zero; both zero (`0:0`) is rejected because no traffic would reach `Alt`.
  - Each side must be ≤ `MaxABRatio` (1,000,000) — protects downstream arithmetic from silent overflow.
  - Malformed values (missing colon, extra colons, non-numeric, negative, decimal, oversized, both-zero) yield `*ErrInvalidABRatio`. The error surfaces through the existing include-error path: rendered as `IncludeErrorMarker` (empty by default), skipped if `onerror="continue"`, or replaced with the tag body if provided. Empty `ab-ratio` falls back to the documented default `50:50`.
- **`max-depth` (per-tag)** – Format requirements enforced since #317:
  - Must parse as a non-negative unsigned integer; leading and trailing whitespace is trimmed.
  - Must be ≤ `MaxMaxDepth` (10,000) — well above any realistic ESI recursion depth and far below any platform's `uint` wrap boundary, so the `uint(v)+1` clamp that strengthens the parent's `MaxDepth` can never overflow.
  - A validated override clamps the parent's `MaxDepth` to `v+1` ("override can only tighten, never widen" semantics, identical to the legacy contract). Explicit `max-depth="0"` therefore reduces the parent's `MaxDepth` to `1` (the historical "one more level" signal).
  - Malformed values (non-numeric, negative, decimal, oversized, beyond `MaxUint64`) yield `*ErrInvalidMaxDepth`. The error surfaces through the configured logger (Debug when running with `Debug: true` or the supplied `Logger` accepts `Warn`; no-op under the default `DiscardLogger`) and the override is dropped: the parent's `MaxDepth` survives untouched, preventing a single misconfigured include from silently disabling all nested ESI processing under it. Empty / whitespace-only `max-depth` is treated as "no override" and the parent's value is preserved verbatim.
- **PHP Extension – in-memory cache (`parse_with_config()`)** since #226:
  - Exposed via `mesi\parse_with_config($input, $max_depth, $default_url, $config)` where `$config` is an associative array.
  - `cache_backend` accepts only `"memory"` or absent/empty; any other string triggers `E_WARNING` and `parse_with_config()` returns `false` (the function never silently degrades to "no cache" on a typo). The "memory" backend is wired through libgomesi `InitCache` per PHP worker process.
  - `cache_size` must be a non-zero integer in `[1, 1_000_000]`; `cache_ttl` must be an integer in `[0, 86_400]` seconds. Out-of-range or wrong-type values produce `E_WARNING` plus `false`.
  - The extension caches the last `(backend, size, ttl)` tuple per worker process; subsequent calls with the same parameters skip `InitCache` so the existing in-process entries survive. Calling with different parameters (e.g. pointing the same worker at a larger size) wipes the cache by design — callers that need long-lived cache state therefore keep parameters consistent.
  - Cache is **per-worker-process**: each PHP-FPM/PHP-CLI worker has its own private cache; entries are not shared across workers. For cross-process / cross-host sharing, use the planned Redis and Memcached backends (#231, #235).
  - The legacy `mesi\parse($input, $max_depth, $default_url)` entrypoint is unchanged — it never touches the cache.
- **PHP Extension – Redis and Memcached cache backends (`parse_with_config()`)** since #231:
  - Both backends reuse the existing in-process `parse_with_config()` config array. The extension no longer routes through the old `InitCache` entry point; it now wires a JSON config blob through `libgomesi.InitCacheWithConfig(backend, size, ttl, configJSON)`.
  - For `cache_backend = "redis"` the extension renders `{"redisAddr":"host:port","redisPassword":"…","redisDB":N}`. `cache_redis_addr` is required, must be `"host:port"` with port in `[1, 65535]`, and rejects whitespace, control chars, `"` and `\` (so the rendered JSON cannot be broken by a hostile operator input — same restrictions as the Apache `MesiCacheRedisAddr` validator). `cache_redis_password` is optional and follows the same character rules. `cache_redis_db` accepts integers in `[0, 15]`; an explicit `0` is distinguished from "unset" so the rendered JSON omits the key in the latter case (matching libgomesi's "default 0" semantics). `cache_redis_addr` / `cache_redis_password` / `cache_redis_db` keys supplied with any other backend are rejected with `E_WARNING` (mismatched backend can never silently demote to "no cache").
  - For `cache_backend = "memcached"` the extension renders `{"servers":["h:p",…]}`. `cache_memcached_servers` is required and must be a non-empty array of `"host:port"` strings passing the same validator as `cache_redis_addr`. A non-string entry, an entry missing the port, an out-of-range port, an entry with whitespace / control / `"` / `\`, or supplying this key with a non-memcached backend all produce `E_WARNING` + `false`.
  - Init succeeds even when no Redis / Memcached daemon is reachable because the underlying `go-redis` and `gomemcache` clients are lazy; subsequent `<esi:include>` traffic will fall back to the origin server (degraded mode) and cache entries will simply never be observed. The same in-process `(backend, size, ttl, configJSON)` last-init state that already protects the `memory` backend now also caches the rendered JSON, so repeated `parse_with_config()` calls with identical Redis / Memcached configuration skip `InitCacheWithConfig` and never replace sharedCache with a fresh, empty instance.
- **Traefik `blockPrivateIPs` (#195)** — The option is configurable (default `true`) and wired through to `mesi.EsiParserConfig.BlockPrivateIPs`. Because the Traefik plugin runs under Yaegi, the dial-time IP-blocking transport (`ssrf_dialer.go`) is excluded and replaced by a stub `NewSSRFSafeTransport` (see `servers/traefik/Dockerfile`), so the option is exposed but the actual dial-time private-IP enforcement is **not active** in the interpreted plugin. Effective SSRF control in Traefik comes from the URL-level `allowedHosts` option (#200), which is now implemented: a `[]string` whitelist (exact or subdomain-suffix match) wired through to `mesi.EsiParserConfig.AllowedHosts`. The matrix therefore marks Traefik SSRF as ⚠️ (partial), not ✅.
- **Apache `MesiMaxDepth` (#166)** — Global ESI nesting depth via the `MesiMaxDepth` directive. Unset → `5` (backward compatible with the previous hardcoded value). Explicit `0` is valid passthrough (no ESI fetch); `1` processes one include level so the inner tag is replaced with the empty `IncludeErrorMarker` (same contract as Caddy `max_depth 1`). Range `[0, 10000]` (`mesi.MaxMaxDepth` / Caddy). Invalid values (negative, empty, non-digits, decimals, overflow) are rejected at config load — no silent default.
- **nginx `mesi_max_depth` (#180)** — Global ESI nesting depth via the `mesi_max_depth` directive (location context; nested locations inherit the enclosing location's value via `ngx_conf_merge_value`, a child that sets the directive overrides its parent). Unset → `5` (backward compatible with the previously hardcoded literal). Explicit `0` is valid passthrough (no `<esi:include>` is fetched; tags are stripped through the include-error path with the empty default marker — the established cross-platform depth-0 contract, see Caddy `max_depth 0`); `1` processes one include level so the inner tag is replaced with the empty `IncludeErrorMarker` (same contract as Apache `MesiMaxDepth` #166 / Caddy `max_depth` #401). Range `[0, 10000]` (`mesi.MaxMaxDepth`); a custom setter — not `ngx_conf_set_num_slot`, whose `ngx_atoi` has no upper bound — rejects negatives, signs, decimals, non-integers, empty values and anything above the cap at config load (`nginx -t` fails, error names the directive and the value — no silent default, no silent wrap). The value is passed to every libgomesi entry point the module uses (`ParseWithConfigCtx`/`ParseWithConfigEx`/`ParseWithConfig`/legacy `Parse`), with a defense-in-depth range guard in `parse()` that fails the request closed rather than clamping.
- **Apache `MesiAllowPrivateIPsForAllowedHosts` (#168)** — When `On` together with `MesiBlockPrivateIPs On` and a non-empty `MesiAllowedHosts`, hosts listed in `MesiAllowedHosts` are permitted to resolve to private/reserved IP addresses (the dial-time SSRF block is bypassed for them). The bypass is **only** effective when BOTH `MesiBlockPrivateIPs On` AND `MesiAllowedHosts` are set; otherwise it is a no-op. Default `Off` (private IPs always blocked regardless of `MesiAllowedHosts` membership). **Security warning:** this trusts DNS for hosts in `MesiAllowedHosts` — only use with internal DNS (Consul, Kubernetes DNS, `/etc/hosts`). The Apache module calls libgomesi's `ParseWithConfigEx` (added in #168); older `libgomesi.so` builds without that symbol fall back to `ParseWithConfig` and log a warning that the bypass is disabled.
- **Apache `MesiCacheKeyTemplate` (#177)** — Template-based `CacheKeyFunc` for `MesiCacheBackend` memory/redis/memcached. Placeholders: `${url}`, `${header:Name}` (case-insensitive), `${cookie:Name}` (case-insensitive); unknown placeholders stay literal. When `MesiCacheKeyTemplate` is empty/absent the URL-only `DefaultCacheKey` (`"mesi:" + url`) is used for backward compat. Without a cache backend the template has no effect. Headers/cookies are collected from the incoming `request_rec` into a JSON context (`{"headers":{...},"cookies":[{"name","value"}]}`) and passed to `libgomesi.ParseWithConfigCtx` which delegates to `mesi.BuildCacheKey` — the same helper Caddy/RoadRunner/Traefik/php-ext share, so all platforms behave identically. Older `libgomesi.so` without `ParseWithConfigCtx` falls back to URL-only keys and logs `MesiCacheKeyTemplate set but libgomesi lacks ParseWithConfigCtx` (#177). **Apache-only interpolation:** unlike all other platforms which take the template verbatim, Apache\'s `ap_resolve_env` replaces every undefined `${VAR}` (e.g. `${url}`) with "" before delivery (`AH00111: Config variable ${url} is not defined`); `${header:...}`/`${cookie:...}` are unaffected because `:` is not a valid env-var character. In `httpd.conf` escape the dollar as `$$`: `MesiCacheKeyTemplate "mesi:$${url}:${header:Accept-Language}"` (Apache keeps `$$` verbatim — `ap_resolve_env` still warns `AH00111` for the inner `${url}` — the module normalizes `$${`→`${` at config load, so any position/repetition like `"mesi:${header:X}:$${url}:${cookie:C}"` or a lone `"$${url}"` becomes `mesi:${url}:...`/`"${url}"` without a stray `$`). Mangled templates (containing `::` or ending in `:` after interpolation, including a lone `"${url}"→""`) are rejected at config load with `MesiCacheKeyTemplate: Apache config interpolation replaced ${url} (AH00111); escape the dollar sign as $${url} in httpd.conf` — no silent wrong keys (e.g. cross-URL bleed from missing `${url}`). **Limitation:** `::`/trailing-`:` templates are unrepresentable in Apache (mangled signal) — use a separator (`-`, `_`) instead (other platforms keep them verbatim).
- **Apache `MesiSharedHTTPClient` (#178)** — When `On`, the Apache module calls libgomesi's `InitHTTPClient` once per worker process (lazily, on the first request that touches a config with the directive set), creating a single SSRF-safe `http.Client` (built from `mesi.NewSSRFSafeTransport`) that all `<esi:include>` fetches in that process share for TCP/TLS connection pooling. Default `Off` (each include creates its own client, the historical behaviour). The effective `MesiBlockPrivateIPs` setting (default `On`) is baked into the shared transport at startup; changing it later requires a restart. Older `libgomesi.so` builds without the `InitHTTPClient` symbol log an error and fall back to per-include clients. The per-call `Timeout` override is preserved (libgomesi copies the shared client and replaces `Timeout` per `Parse` call).
- **Apache `MesiTimeout` (#167)** — Global per-include fetch budget via the `MesiTimeout` directive (server context; a vhost's value overrides the global one, unset vhosts inherit via the `-1` sentinel merge, same rule as `MesiMaxDepth`). Unset → `30` (backward compatible with libgomesi's historical hardcoded value). Range `[1, 86400]` (`24h` — mirrors `config.MaxTimeoutSeconds` and the `MesiCacheTTL` ceiling); **`0` is rejected at config load**: the core fails every include immediately with `ErrTimeBudgetExceeded` when `Timeout <= 0` (`mesi/fetch.go`) — it is not "no timeout" (Caddy rejects a non-positive `timeout` for the same reason), and an unlimited budget would pin a goroutine per queued include while a backend hangs. Parsed via `parse_nonneg_int` — negatives, `0`, empty, non-digits, decimals, trailing garbage and overflow fail `apachectl configtest` with an error naming the directive (no silent `atoi` coercion). The value reaches libgomesi through the new **`ParseJson`** JSON entry point as `{"timeoutSeconds":N}` (seconds — nanosecond conversion happens Go-side in `config.ResolveTimeout`); the blob also carries the other resolved settings (`maxDepth`, `defaultUrl`, `allowedHosts`, SSRF flags, optional `cacheKeyTemplate` + `requestCtx`), and is only used when `MesiTimeout` is set — configs without the directive keep the exact legacy `ParseWithConfigCtx`/`Ex`/`Config` path. Older `libgomesi.so` without the `ParseJson` symbol fall back to that chain and log `MesiTimeout set but libgomesi lacks ParseJson` (directive ignored, 30s applies — same graceful-fallback pattern as `ParseWithConfigEx` #168).
- **Apache `MesiMaxResponseSize` (#169)** — Caps a single `<esi:include>` response body in **bytes** (per-include, not per page; over-limit includes fail their fetch and render the empty `IncludeErrorMarker` / fallback body). Server context (`RSRC_CONF`); a vhost's value overrides the global one, unset vhosts inherit via the `-1` sentinel merge (same rule as `MesiMaxDepth`/`MesiTimeout`) — and because `0` IS storable ("unlimited"), the sentinel being `-1` (not `0`) is what lets a vhost's explicit `MesiMaxResponseSize 0` override a global limit. **Unset → unlimited** (byte-identical to previous behaviour): libgomesi leaves `EsiParserConfig.MaxResponseSize` at `0` on every positional path and the core only limits when `MaxResponseSize > 0` (`mesi/fetch.go:288`) — there is **no implicit 10 MB default on this path** (the `CreateDefaultConfig()` 10 MB only reaches Go callers of that constructor; Caddy's unset `max_response_size` likewise leaves `0`). Explicit `0` = the same documented "unlimited" contract as Caddy `max_response_size 0`. Range `[0, 9223372036854775806]` (`math.MaxInt64 - 1`): neither core nor Caddy caps the value, but the core computes `MaxResponseSize + 1` for `io.LimitReader` (`mesi/fetch.go:290`) — at `math.MaxInt64` that wraps negative and the include would silently render an empty body, so the cap is the largest value keeping the `+1` bound positive (mirrored as libgomesi `config.MaxMaxResponseSize` and Apache `MESI_MAX_MAX_RESPONSE_SIZE`, validated Go-side in `ParseConfig.ResolvedMaxResponseSize` as defense-in-depth). Parsed via the strict 64-bit `parse_nonneg_off` helper — **not** the issue's `apr_strtoff` sketch (with `end=NULL` it silently accepts `100abc`, `+1` and leading whitespace) and not `parse_nonneg_int` (its 9-digit guard is int32-only): negatives, `+1`, decimals, non-digits, empty, trailing garbage and values above the cap fail `apachectl configtest` with an error naming the directive (a negative must fail because the core's `> 0` check would silently treat it like `0`). The value travels through libgomesi's **`ParseJson`** entry point as the new additive `{"maxResponseSize":N}` byte-count key (`*int64` in `config.ParseConfig`; absent → `0` = byte-identical exports/behaviour); `build_parse_json_config` renders `timeoutSeconds`/`maxResponseSize` only when the corresponding directive is set, so `MesiMaxResponseSize`-only configs keep the 30s positional timeout and `MesiTimeout`-only configs keep unlimited size. Requires `libgomesi.so` with `ParseJson`; older builds log `MesiMaxResponseSize set but libgomesi lacks ParseJson; MesiMaxResponseSize ignored (unlimited response size applies, the pre-#169 behaviour)` and stay unlimited (graceful fallback, never a crash or a wrong cap). Functional coverage: vhosts 8089/8090/8091 in `httpd.conf` (reject 200 B over a 100 B cap / accept 500 KB under a 1 MB cap / accept 50 MB with explicit `0`) plus the unset default vhost accepting a 10 MB + 1 body — pins "unset → unlimited" against the issue's proposed 10 MB default; bodies served by the new `tests/server.py` `/bytes/<size>` generator (#169)
- **PHP extension `timeout` (#181)** — Global per-include fetch budget via the `timeout` config key of `parse_with_config()`. Absent → `30` (libgomesi's historical hardcoded value — omitted key is byte-identical to previous behaviour); range `[1, 86400]` (mirrors `config.MaxTimeoutSeconds` / `MesiTimeout`); **`0` is rejected** for the same reason as Caddy/Apache (`Timeout <= 0` fails every include with `ErrTimeBudgetExceeded` in `mesi/fetch.go`, it is not "no timeout"). Non-integer explicit values (numeric strings `"10"` do not coerce, floats `1.5`/`10.0`, `"abc"`, `"3foo"`, `""`, bools, null, arrays, overflow) and out-of-range values (`0`, `-1`, `86401`, `PHP_INT_MAX`) emit `E_WARNING` naming `timeout` and the function returns `false` — the same strict contract as `cache_ttl` (absent is a documented default; a malformed explicit value is never silently kept or replaced). When the key is present the call routes through libgomesi's **`ParseJson`** entry point (#167) as `{"timeoutSeconds":N}` **in seconds** (deviation from #181's nanosecond sketch); the blob mirrors every other resolved setting (`maxDepth`, `defaultUrl`, `allowedHosts`, SSRF flags, optional `cacheKeyTemplate` + `requestCtx`), so behaviour matches the positional path except for the timeout. The absent-key path keeps the exact `ParseWithConfigCtx` call (Apache #167 `used_parse_json` pattern). The symbol is resolved lazily per process via `dladdr(&Parse)` → `dlopen` (the already-loaded library, never a second copy) → `dlsym`; an older `libgomesi.so` without `ParseJson` falls back to the positional path with an `E_WARNING` that the timeout is ignored (30s applies) — never a crash, never a link-time hard dependency. Legacy `mesi\parse()` keeps the hardcoded 30s.
- **nginx `mesi_cache_key_template` (#244)** — Template-based cache key for `mesi_cache_backend memory/redis/memcached`, wired through the same `libgomesi.ParseWithConfigCtx` + `mesi.BuildCacheKey` path as Apache #177 (identical placeholder semantics: `${url}`, `${header:Name}` case-insensitive, `${cookie:Name}` case-insensitive, unknown placeholders literal, empty/absent = URL-only `DefaultCacheKey`). The module serialises the incoming request's headers/cookies into the shared JSON context (Cookie header tokenised into the cookies array; request context only built when the template contains `${header:`/`${cookie:`). The template is taken **verbatim** — nginx does not interpolate `${VAR}` in directive arguments, so no Apache-style `$$` escaping and no mangled-template (`::`/trailing `:`) rejection. **Fallback:** older `libgomesi.so` without `ParseWithConfigCtx` logs a per-request warning (`mesi: mesi_cache_key_template is set but libgomesi lacks ParseWithConfigCtx — cache key template ignored, using URL-only cache keys`) and uses URL-only keys — never a silently wrong key. Config-load validation mirrors Apache: ≤4096 bytes, control chars/DEL rejected by `nginx -t`. Without a cache backend the template has no effect; no function-pointer `CacheKeyFunc` is available from C (template-based composition is the documented compromise — use a Go-based proxy for full flexibility).
- **RoadRunner memory cache (`cache_backend memory`)** since #236:
  - `cache_backend` accepts `"memory"` plus the build-tag-gated `"redis"` / `"memcached"`. Any unknown value is rejected by `initCache` so a typo never silently degrades to "no cache" (the caddy intermediate had the same constraint).
  - `cache_size` is bounded to `[1, 1_000_000]` through `normalizeCacheSize`. Values `<= 0` are kept as the documented "unset → use default 10 000 entries" sentinel (matching caddy / apache / cli / libgomesi behaviour). Values above `MaxCacheSize` are rejected at plugin `Init`, so a stray 5_000_000 no longer silently feeds the in-memory map constructor.
  - `cache_ttl` is parsed through `parseCacheTTL`: an empty string means "no explicit TTL" (default 0, no expiry), the string must be a non-negative Go duration, and the ceiling is `MaxCacheTTL` (24 h). Strings like `"-1s"` are rejected instead of flowing into `mesi.NewMemoryCache`, where they would silently translate to "no expiry" (`cache_memory.Set` treats `< 0` like `0`). Strings unparseable by `time.ParseDuration` keep the legacy `invalid cache_ttl …` error so operator typos surface during plugin startup.
  - Cache scope is **per RoadRunner worker goroutine**: each worker owns its own `MemoryCache`, dedups within that worker only. Cross-worker sharing requires the `redis` or `memcached` backend (both already supported).
  - The `examples/roadrunner-memory-cache.yaml` fixture ships a runnable `.rr.yaml` snippet with the documented bounds; the README `Cache backends → Memory` section still drives the discovery.
- **Cache key template (Caddy/RoadRunner/Traefik/CLI/Apache/nginx)** — Custom cache-key template via `mesi.BuildCacheKey` (`${url}`, `${header:Name}`, `${cookie:Name}`; unknown placeholders left literal). The rendered template plus the SSRF-policy fingerprint (`AllowedHosts`+flags+client type, `mesi/fetch.go:200`) form the final key. Empty/absent template falls back to URL-only `mesi.DefaultCacheKey`. A template without `${url}` collapses all URLs to one entry (cross-URL collision). CLI (`-cache-key-template`) supports `${url}` only (`cli/mesi-cli.go:128-130`). Apache uses the same `mesi.BuildCacheKey` helper via `libgomesi.ParseWithConfigCtx` — see `servers/apache/README.md` for the `MesiCacheKeyTemplate` directive; nginx does the same via the `mesi_cache_key_template` directive (see below).
- **Apache `build.sh` (#102)** — Local builds (developers who prefer `./build.sh` over the Dockerfile) get loud errors instead of the legacy `cp … 2>/dev/null || sudo cp …` pattern that masked missing-source, read-only-prefix, missing-`apxs`, and missing-`go` failures. Concretely:
  - `set -euo pipefail` is enabled, so unset variables and pipe failures abort the script (the legacy `set -e` only caught the immediate exit status of `cmd1 || cmd2`).
  - Preflight writability check: `if [[ -w "$INSTALL_PREFIX" ]]` decides whether the install needs `sudo`; the legacy code's first `cp` always failed on a correctly-configured system and only the `sudo cp` was a real code path. The new script never invokes `sudo` when the prefix is writable.
  - `INSTALL_PREFIX` is overridable (defaults to `/usr/lib`); convenient for `/usr/local/lib` conventions. Set `LIBGOMESI_SO` to point at a pre-built `.so` to skip the inline `go build`.
  - Errors are not silenced: missing `libgomesi.so` plus missing `go` ⇒ two distinct error lines; missing `apxs` / `apxs2` ⇒ one clear error naming the missing Debian/RHEL package; non-writable prefix ⇒ the script prints the destination and "requesting sudo to install …" before invoking sudo, so the operator knows why the password prompt appeared.
  - `install -m 0644` replaces `cp`; the file mode is atomic and the call surface is well-defined.
  - A new test runner (`servers/apache/test_build_sh.sh`) exercises six deterministic scenarios with stub `apxs` / `sudo`, asserting both exit status and stderr content. The "real failure" scenarios cover a non-existent `INSTALL_PREFIX`, a missing `apxs` / `apxs2`, and a missing `libgomesi.so` + missing `go` — each maps to a specific error line that legacy `cp ... 2>/dev/null || sudo cp …` would have silenced.
