# Changelog

## [0.13.0] - Unreleased

### Added
- CLI `-allowedHosts` flag: comma-separated host whitelist (`-allowedHosts "backend.internal,cdn.example.com"`) restricting which `<esi:include>` destinations the CLI fetches. Matching is done in the shared core — exact or subdomain-suffix match with a `.` boundary that rejects suffix injection, case-insensitive, ports ignored — the same semantics as Apache `MesiAllowedHosts` / nginx `mesi_allowed_hosts` (#199) / Traefik `allowedHosts` (#200). Unset = all hosts allowed (backward compatible), subject to the dial-time `BlockPrivateIPs` check (see `-allow-private-ips`); the whitelist check runs by hostname first and does NOT bypass the private-IP block. Entries are matched verbatim — separate hosts with commas only (no trimming). Unit tests cover flag parsing (absent/single/multiple hosts) and `-h` listing; `cli/test.sh` functional cases cover allow and block (#179)
- CLI `-include-error-marker` flag: custom marker string rendered for failed ESI includes. When set, failed `<esi:include>` tags (without `onerror="continue"` or fallback body) render the marker in the HTML output instead of producing empty output. Useful for debugging — e.g. `-include-error-marker='<!-- esi error -->'`. Default: "" (silent) (#202)
- CLI `-shared-http-client` flag: when set, creates a shared `http.Client` with connection pooling and SSRF-safe transport for all ESI includes within a single invocation. Reduces latency for pages with many includes to the same origin (#227)
- CLI `-cache-key-template` flag: custom cache key template with `${url}` placeholder substitution. Example: `-cache-key-template='myapp:${url}'` (#222)
- Apache `MesiAllowPrivateIPsForAllowedHosts` directive: when `On` together with `MesiBlockPrivateIPs On` and a non-empty `MesiAllowedHosts`, hosts listed in `MesiAllowedHosts` are permitted to resolve to private/reserved IP addresses (the dial-time SSRF block is bypassed for them). Only effective when BOTH `MesiBlockPrivateIPs On` AND `MesiAllowedHosts` are set; otherwise a no-op. Default `Off` (private IPs always blocked regardless of `MesiAllowedHosts` membership). The Apache module now calls libgomesi's new `ParseWithConfigEx` entry point (ABI-safe extension of `ParseWithConfig` that adds the `allowPrivateIPsForAllowedHosts` parameter); older `libgomesi.so` builds without that symbol fall back to `ParseWithConfig` and log a warning that the bypass is disabled. Unit tests in `test_directives.c` cover On/Off/default and merge; `test.sh` adds three functional cases (bypass On succeeds for allowed private host, bypass Off blocks it, bypass On still blocks a private host outside `MesiAllowedHosts`) (#168)
- Apache `MesiSharedHTTPClient` directive: when `On`, the module calls libgomesi's `InitHTTPClient` once per worker process (lazily, on the first request that touches a config with the directive set), creating a single SSRF-safe `http.Client` (built from `mesi.NewSSRFSafeTransport`) shared by all `<esi:include>` fetches in that process for TCP/TLS connection pooling. Default `Off` (each include creates its own client — the historical behaviour). The effective `MesiBlockPrivateIPs` setting (default On) is baked into the shared transport at startup; changing it later requires a restart. Older `libgomesi.so` builds without the `InitHTTPClient` symbol log an error and fall back to per-include clients. Unit tests in `test_directives.c` cover On/Off/default and merge; `test.sh` adds a functional case (includes still resolve with the shared client, and the `mesi: shared HTTP client initialized` NOTICE log proves the wiring) (#178)
- RoadRunner `block_private_ips` plugin config option: controls whether ESI includes to private/reserved IP addresses (loopback, RFC 1918, CGNAT, link-local, cloud metadata `169.254.169.254`, benchmark/documentation ranges) are blocked at dial time. It is wired through to `mesi.EsiParserConfig.BlockPrivateIPs` and defaults to `true` (secure by default), preserving the previous hardcoded behaviour; an explicit `false` opts out of dial-time SSRF protection (e.g. for internal service meshes). ### Added
- nginx SSRF protection directive: `mesi_block_private_ips on | off` controls whether ESI includes to private/reserved IP addresses (loopback, RFC 1918, CGNAT, link-local, cloud metadata `169.254.169.254`, benchmark/documentation ranges) are blocked at dial time. The nginx module now calls `libgomesi.ParseWithConfig` (instead of `Parse`) so the `BlockPrivateIPs` flag is honoured. Default is `on` (#193)
- nginx `mesi_allowed_hosts` directive: a host whitelist that restricts which ESI include destinations are fetched, closing the SSRF exfiltration gap even when `mesi_block_private_ips` is off. The directive takes one nginx argument, so multiple hostnames are written as a single quoted, space-separated string (e.g. `mesi_allowed_hosts "backend sub.backend";`) — same convention as `mesi_cache_memcached_servers`; the content format mirrors Apache's `MesiAllowedHosts` for cross-server consistency. Matching is exact or subdomain-suffix (`sub.backend` matches `backend`); the `.` boundary prevents suffix injection (`attacker-example.com` and `notexample.com` do NOT match `example.com`); ports are ignored (`http://backend:8000/` matches `backend`). Unset (empty) allows all hosts (subject to `mesi_block_private_ips`), preserving backward compatibility; whitespace-only values are rejected at config load — the rejection covers the full ASCII whitespace set (space, tab, CR, LF, VT, FF), not just spaces and tabs, so a value like `"\r"` can no longer slip through `nginx -t` and become an empty allowlist in the Go core. The check runs by hostname before the dial-time `BlockPrivateIPs` check — two-phase defense-in-depth. With a stale `libgomesi` build lacking `ParseWithConfig`, a configured `mesi_allowed_hosts` now fails requests fail-closed with a defined **HTTP 500**: the check runs in the header filter phase (before `ngx_http_next_header_filter` sends the status line), so the client receives a proper error response instead of an empty reply / dropped connection, while the upstream body passes through untouched. Functional tests in `servers/nginx/test.sh` cover allow / block / subdomain / suffix-injection / multiple hosts / unset; subdomain fixtures resolve via docker network aliases in `docker-compose.yml` (#199)
- Traefik `blockPrivateIPs` plugin config option: controls whether ESI includes to private/reserved IP addresses are blocked. It is wired through to `mesi.EsiParserConfig.BlockPrivateIPs` and defaults to `true`, preserving the previous hardcoded behaviour. Under Yaegi the dial-time IP-blocking transport is stubbed (see `servers/traefik/Dockerfile`), so the option is configurable but the actual dial-time enforcement is not active in the interpreted plugin — URL-level `allowedHosts` protection (#200) is the effective control there (#195)
- Traefik `allowedHosts` plugin config option: a `[]string` host whitelist that restricts which ESI include destinations are fetched, closing the SSRF gap in the interpreted plugin (dial-time IP blocking is stubbed under Yaegi). Matching is exact or subdomain-suffix (`sub.example.com` matches `example.com`); the `.` boundary prevents suffix injection (`evil.com` does NOT match `example.com`). Empty list allows all hosts (subject to `blockPrivateIPs`), preserving backward compatibility. Wired through to `mesi.EsiParserConfig.AllowedHosts`. Unit tests cover empty / single / multiple hosts, subdomain matching, and suffix-injection guard; functional tests cover allow / block / backward-compatible behaviour (#200)
- PHP extension `block_private_ips` option for `parse_with_config()`: controls whether ESI includes to private/reserved IP addresses (loopback, RFC 1918, CGNAT, link-local, cloud metadata `169.254.169.254`, benchmark/documentation ranges) are blocked at dial time, closing the SSRF gap in the PHP extension. The option defaults to `true` (secure by default) — the extension now routes through `libgomesi.ParseWithConfig` (instead of `Parse`) and (re)builds the shared HTTP client's SSRF-safe transport only when the requested value changes between calls. A non-boolean value is rejected with `E_WARNING` and `parse_with_config()` returns `false`. The legacy `\mesi\parse()` entrypoint is unchanged in signature and keeps the module-init behaviour (no blocking) until a `parse_with_config()` call opts in (#185)

### Changed
- **`<esi:include fetch-mode="ab" ab-ratio="…">` now rejects malformed input.** Previously the parser silently substituted the documented `{A:50, B:50}` default for every malformed value (missing colon, extra colons, negative numbers, decimals, non-integer operands, oversized integers, both-sides-zero). It now returns `*ErrInvalidABRatio` through the existing include-error path, surfacing the operator's actual input in logs and the `IncludeErrorMarker` (#315).
- **`<esi:include max-depth="…">` now rejects malformed input and clamps to a documented upper bound.** Previously the parser silently substituted the parent's `MaxDepth` for every malformed value (non-numeric, negative, decimal, oversize — including values past `MaxUint64`), and silently accepted any parsed-but-unbounded value via `uint(v)+1`. It now returns `*ErrInvalidMaxDepth` through the configured logger (visible via `Debug` and any logger implementing `Warn`) and preserves the parent's `MaxDepth` for the rejected override. Empty / whitespace-only attributes continue to be treated as "no override" so existing templates that omit the attribute or pass a blank one are not silently downgraded. Accepted values are bounded by `MaxMaxDepth` (10,000) so the `+1` arithmetic that clamps the parent's depth can never approach any platform's `uint` wrap boundary (#317).
- **BREAKING CHANGE: nginx `mesi_block_private_ips` now defaults to `on`.** Previously the nginx module called `libgomesi.Parse` which never set `BlockPrivateIPs`, so every `<esi:include>` to a private/reserved IP (loopback, RFC 1918, cloud metadata `169.254.169.254`, etc.) succeeded with no protection. The module now calls `ParseWithConfig` and the new `mesi_block_private_ips` directive defaults to `on`. Deployments that intentionally include from internal/private backends must explicitly set `mesi_block_private_ips off;` (#193).

### Fixed
- nginx `mesi_allowed_hosts` config validation now rejects **Unicode**-whitespace-only values, not just the ASCII whitespace set. Previously a value made solely of e.g. non-breaking spaces (U+00A0, bytes `c2 a0`) passed `nginx -t`, but libgomesi splits the value with Go's `strings.Fields` (which strips all Unicode whitespace), so the allowlist silently became empty — allow all hosts, fail-open. The check now mirrors `strings.Fields` tokenization: every Unicode whitespace rune (U+0085, U+00A0, U+1680, U+2000–U+200A, U+2028, U+2029, U+202F, U+205F, U+3000) counts as a separator, and a value that tokenizes to zero hostnames is rejected at config load; legitimate values (hosts separated by ASCII or Unicode whitespace, leading/trailing whitespace around a real hostname) still pass. Functional tests in `servers/nginx/test.sh` assert `nginx -t` fails for ASCII- and Unicode-whitespace-only values and succeeds for valid ones (#354).
- Shared-core security hardening for `AllowedHosts` (delivered with the nginx `mesi_allowed_hosts` directive, affects every platform using the whitelist): redirect responses are no longer auto-followed by Go's `http.Client`. `singleFetchUrlWithContext` now follows at most 10 redirects manually and re-validates every hop target (http/https scheme + `AllowedHosts`) before dialing it, so an allowlisted backend can no longer redirect to an arbitrary public host — previously `Location` was followed unconditionally. Relative `<esi:include src="…">` paths are now resolved against `DefaultUrl` first and the fully expanded URL is validated against the whitelist before any dial, so with a non-empty allowlist a relative include only works when the resolved host is allowlisted (on nginx, `DefaultUrl` is built from the request's `Host` header). Hostname matching is normalized in the shared core: case-insensitive (EqualFold) with a single trailing root dot tolerated on both sides (`Backend` / `backend.` match `backend`), keeping the exact `.`-boundary semantics that reject suffix injection. The per-include fetch timeout now bounds the WHOLE include fetch, including every redirect hop, the final body read, and the admission-control waits (the `MaxConcurrentRequests` semaphore and the same-key dedup wait) — a queued include can never wait behind a slow earlier fetch beyond the budget; previously each hop started a fresh `http.Client` with its own `client.Timeout`, so a chain of redirects could consume roughly 11x the configured budget before erroring, and queued includes could wait unboundedly. Cache keys are now namespaced by a canonical SSRF-policy fingerprint (sorted, deduplicated `AllowedHosts`; ASCII hostnames case-normalized — exactly EqualFold-compatible — non-ASCII hostnames preserved verbatim; hosts encoded as base64 byte slices so even malformed UTF-8 entries are represented losslessly and distinct policies never collide) plus the SSRF flags (`BlockPrivateIPs` + `AllowPrivateIPsForAllowedHosts`) and the client type (custom `HTTPClient` vs default per-request client), so content cached under one policy/transport can never be served under a different one: caches are process-wide (nginx module / libgomesi shared cache), a body fetched through a redirect under a broad policy would previously be served from cache to a stricter policy that would have rejected the redirect target, and a body fetched through a custom transport could be served to a default-client config with `BlockPrivateIPs` enabled before it was ever dialed — a policy or client-type change in either direction (stricter or looser) now invalidates old entries. Unit tests cover redirect allow/block, relative `Location`, redirect-loop limit, whole-chain timeout budget, policy-namespaced cache keys, custom-vs-default client fingerprints, relative-include allow/block, and hostname normalization; nginx functional tests 27/28 prove a 302 from an allowed backend to a non-listed alias falls back while the same redirect succeeds when the alias is listed (#199).
- `MESIParse` no longer silently normalizes a negative `MaxConcurrentRequests` to zero. Invalid values are surfaced through the configured logger via `Debug` (or `Warn` for loggers implementing `LoggerWarn`) before normalizing, matching the pattern established by the `max-depth` (#317) and `ab-ratio` (#315) validation fixes (#329).
- Race condition in concurrent ESI include fetches: when two parallel workers process identical `<esi:include>` URLs both miss the cache and both perform upstream round-trips, returning different responses. A per-key inflight lock now serialises cache-miss fetches for the same URL so the second worker blocks until the first populates the cache and then serves from it — fixing the same-page cache-dedup guarantee for both in-memory and external cache backends (#329).
- Nginx module: `cache_initialized` now tracks the last-configured backend. Switching between `mesi_cache_backend memory` and `mesi_cache_backend memcached` (different `location` blocks in the same server) re-initialises the shared cache via `InitCacheWithConfig` instead of silently keeping the first-initialised backend forever (#329).
- `selectUrl` integer-sum overflow at high ratios guarded against `math.MaxInt` saturation (#315).
- `OverrideConfig` `max-depth` path previously accepted any parseable value and propagated it through the `uint(v)+1` clamp with no upper bound. Inputs above `MaxMaxDepth` (10,000) or syntactically invalid now produce `*ErrInvalidMaxDepth` so operator typos and hostile templates both surface through the logger while the parent's `MaxDepth` survives untouched — preventing a single misconfigured include from silently disabling all nested ESI processing under it (#317).
- `mesi` test suite: removed a hand-rolled `contains` / `containsHelper` substring-search reimplementation from `fetch_test.go` and `ssrf_test.go`; the same call sites now use the standard-library `strings.Contains`. A new `TestNoDuplicatedHelper` regression test fails if any local substring helper is reintroduced (#117).
- `servers/apache/Dockerfile` now verifies the Go tarball SHA256 checksum before extraction, replaces the hardcoded `go1.23.0.linux-amd64` download with parameterised `GO_VERSION` and `GO_SHA256` build args, and uses `curl -fsSL` instead of `wget` for better failure handling. The `TARGETARCH` build arg is wired into the download URL so the image can be built for non-amd64 platforms via `--platform` (#101).
- `servers/apache/build.sh` no longer masks install failures. The script previously ran `cp "$LIBGOMESI_SO" /usr/lib/libgomesi.so 2>/dev/null || sudo cp "$LIBGOMESI_SO" /usr/lib/libgomesi.so`, silently swallowing every class of error (permission denied, missing source, read-only destination, disk full, ENOSPC) and falling back to a possibly-successful `sudo install` against an unrelated path. The rewritten script enables `set -euo pipefail`, tests install-prefix writability via `[[ -w "$INSTALL_PREFIX" ]]` before invoking `install -m 0644`, names the destination directory in the sudo-prompt message so the operator knows what password unlocks, allows overriding the install prefix with `INSTALL_PREFIX` (defaults to `/usr/lib`; convenient for `/usr/local/lib` layouts), records explicitly when the source `libgomesi.so` is missing or the `go` toolchain isn't on PATH, and emits a clear error when `apxs` / `apxs2` are not installed. A new `servers/apache/test_build_sh.sh` exercises six deterministic scenarios (non-root success, custom prefix, non-existent prefix, missing apxs, missing source + missing go, stderr preserved); each uses a stub `sudo` so the sudo branch is testable regardless of host euid (#102).

The extension renders a JSON config blob (mirroring `libgomesi`'s `redisConfig` struct) and routes through `InitCacheWithConfig`. Strict validation rejects mismatched backends (e.g. `cache_redis_addr` with `cache_backend = "memory"`), out-of-range ports, malformed `host:port` tokens, non-string passwords, and passwords containing control chars / `"` / `\` so the rendered JSON cannot be broken by hostile operator input. Strict validation: `MesiCacheBackend` accepts only `memory`, `redis`, `memcached`, or empty; `MesiCacheRedisAddr` requires a colon and a 1..65535 port (rejects whitespace, control chars, and JSON-meta chars so the rendered JSON is safe); `MesiCacheRedisPassword` rejects embedded control chars with a generic error that does not leak the value into error logs; `MesiCacheRedisDB` requires a non-negative integer in `[0, 15]`. Strict validation: each entry must contain a colon and a 1..65535 port (rejects whitespace, control chars, JSON-meta chars, decimal/alpha ports, empty values, and >64 entries); an empty server list with the memcached backend produces a deterministic libgomesi `servers required` error rather than a silent `localhost:11211` default. Malformed config returns `-1` from libgomesi and is logged; ESI continues without cache (#176)

- PHP extension `parse_with_config()` plus the in-memory cache backend: takes an associative `config` array alongside the existing `parse()` arguments and supports `cache_backend` (only `"memory"` is exposed — any other value triggers an `E_WARNING` rather than silently caching nothing), `cache_size` (integer in `[1, 1_000_000]`, rejection-warning outside this range), and `cache_ttl` (integer in `[0, 86_400]` seconds, rejection-warning outside this range). The extension tracks the last completed `InitCache` configuration in process-local state so repeated calls with the same parameters don't wipe the in-memory cache between requests — a fresh `InitCache` build always starts empty, so without this guard every cache hit would silently regress to a miss. A fork-based PHPT asserts the cache dedups `<esi:include>` URLs in-process; a second PHPT asserts every validation path (#226)
